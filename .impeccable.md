# Aeroinsights — Design Context

## Design Context

### Users
Aviation finance professionals: aircraft lessors, portfolio risk analysts, IFRS 9 compliance officers. They
work in high-stakes, data-dense environments — reviewing ECL calculations, tracking lease stages, monitoring
counterparty risk across a global fleet. They use the product during the working day, typically on a desktop
or large laptop, often with multiple windows open. Mistakes have regulatory consequences; trust and precision
are non-negotiable.

### Brand Personality
**Precise · Trustworthy · Authoritative**

The interface should feel like Bloomberg Terminal meets modern SaaS — dense and capable, but clean enough to
reduce cognitive load. Not playful, not corporate-template. The Oxford Blue (#002147) brand colour signals
authority without heaviness.

### Aesthetic Direction
- **Theme**: Light (finance professionals work in well-lit offices; dark mode would feel out-of-place for ECL reporting)
- **Tone**: Refined, data-first, restrained. Every element earns its place.
- **Anti-references**: No glassmorphism, no purple-gradient AI aesthetics, no bouncy animations, no rounded-everything
- **References**: Well-crafted fintech dashboards (Plaid, Linear, Stripe dashboard — not the marketing sites)
- **Typography**: Geist Variable — technical, clean, excellent tabular numerals for financial data
- **Colors**: Oxford Blue #002147 brand, Slate neutrals for surfaces, precise semantic colors for ECL stages

### Design Principles
1. **Data first, chrome last** — the numbers and trends are the product; UI elements must not compete
2. **Trust through precision** — pixel-perfect alignment, consistent spacing, nothing feels accidental
3. **Progressive reveal** — surface critical information immediately, depth on demand
4. **Subtle motion, never decorative** — animations communicate state changes; they never perform for performance's sake
5. **Conservative easing** — `cubic-bezier(0.23, 1, 0.32, 1)` strong ease-out throughout; zero bounce, zero elastic

### Animation Constraints
- Never animate charts, heavy data tables, or anything that re-renders frequently
- Entrance animations: `opacity 0→1` + `y ±6–8px` only; nothing that changes layout
- All durations ≤ 300ms for feedback; ≤ 500ms for page-level entrances
- `prefers-reduced-motion` already handled globally in `theme.css` — honour it
- GPU-only: `transform` + `opacity` only; never animate `height`, `width`, `padding`
- For height animations use `grid-template-rows: 0fr → 1fr` or framer-motion `layout`
